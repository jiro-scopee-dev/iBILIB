## Problem

`frontend/src/app/page.tsx:256-268` — the shelf arrows and dots call `goTo(index)`, which tweens a proxy object and writes `st.scroll()` every frame. Current code, verbatim:

```tsx
// frontend/src/app/page.tsx:256-268 — current
const goTo = (index: number) => {
  const tween = tweenRef.current;
  const st = tween?.scrollTrigger;
  if (!st || !tween) return;
  const target = st.start + (st.end - st.start) * (index / Math.max(1, tabs.length - 1));
  const proxy = { v: st.scroll() };
  gsap.to(proxy, {
    v: target,
    duration: 0.8,
    ease: 'power2.inOut',
    onUpdate: () => st.scroll(proxy.v),
  });
};
```

Three problems, in order of felt impact:

1. **Competing tweens stack.** Each click spawns a new `gsap.to(proxy, …)`. There is no `killTweensOf` and no `overwrite`. Rapid arrow/dot clicks (2-3 in half a second) run several 0.8s tweens on the same proxy, each writing `st.scroll()` each frame — the shelf visibly warps, reverses, and fights itself before settling. Call sites: arrows `page.tsx:390` and `page.tsx:398`, dots `page.tsx:411`.
2. **User scroll is overridden.** The tween holds the wheel/trackpad/touch input hostage for the full 0.8s; a user who starts scrolling mid-tween is dragged back toward the tween's target. Nothing listens for user input to cancel it.
3. **0.8s is long for a control click.** UI interaction budget is 200–500ms (modals/drawers) and shorter for repeated controls; 0.8s reads sluggish on a control clicked tens of times/day.

Why it matters: this is the flagship interaction of the current design. Interruptibility is the difference between "the shelf I asked for" and "the shelf arguing with my wheel."

## Target

Self-contained, with the tween killed on both rapid repeat and on any user-initiated scroll input:

```tsx
// frontend/src/app/page.tsx — target
const goTo = (index: number) => {
  const tween = tweenRef.current;
  const st = tween?.scrollTrigger;
  if (!st || !tween) return;
  const target = st.start + (st.end - st.start) * (index / Math.max(1, tabs.length - 1));
  const proxy = { v: st.scroll() };
  const step = () => st.scroll(proxy.v);
  gsap.killTweensOf(proxy);
  const cancel = () => gsap.killTweensOf(proxy);
  window.addEventListener('wheel', cancel, { once: true });
  window.addEventListener('touchstart', cancel, { once: true });
  gsap.to(proxy, {
    v: target,
    duration: 0.5,
    ease: 'power2.inOut',
    overwrite: 'auto',
    onUpdate: step,
    onComplete: () => {
      window.removeEventListener('wheel', cancel);
      window.removeEventListener('touchstart', cancel);
    },
  });
};
```

Notes on the target:

- `gsap.killTweensOf(proxy)` before creating the new tween kills any in-flight proxy tween (including one created by the same handler) — this is the stacking fix.
- `overwrite: 'auto'` is belt-and-braces on top of the kill.
- `wheel`/`touchstart` are **user-initiated only**: programmatic `st.scroll(proxy.v)` does not fire `wheel` events, and a touchstart cannot be generated by code, so the cancel listener cannot kill its own tween.
- `{ once: true }` removes the listener automatically; `onComplete` removes it if the tween finished normally instead. If the tween is killed before completing, the once-listener remains registered until the next wheel/touchstart — it will then kill a non-existent tween (no-op), which is harmless. Do not add extra cleanup for that case.
- Duration 0.5s, same `power2.inOut` ease. Do not change the snap config or the ScrollTrigger scrub elsewhere in the file.
